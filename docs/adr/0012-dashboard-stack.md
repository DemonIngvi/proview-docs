# ADR-0012. Админка: ES-модули + ECharts, встроенные в Go-бинарник

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Нужна красивая настраиваемая визуализация для потребителя среза, без отдельной фронтенд-инфраструктуры; требование «сервисы на Go и JS».

## Решение

Одностраничная админка на нативных ES-модулях без сборки, графики Apache ECharts 5.6 (вендорится в репозиторий), раздаётся тем же Go-сервисом через `embed`.

## Обоснование

- Один артефакт: API и UI выкладываются вместе и не расходятся по версиям.
- ECharts — богатая визуализация (линии, воронка, тепловая карта), SVG-рендер, Apache-2.0.
- Без npm-сборки и node_modules: нет цепочки поставки фронтенда, CSP `self`; логика форматирования тестируется `node --test`.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| React/Vite SPA | экосистема компонентов | сборка, сотни зависимостей, отдельный пайплайн | избыточно для одного дашборда |
| Grafana с плагином ClickHouse | готовые панели, алерты | интерфейс для инженеров, не продукт для менеджера; кастомные срезы и подписи сложнее | целевой пользователь — не инженер |
| Apache Superset / Metabase | конструктор отчётов | отдельная система с БД метаданных, своя авторизация | тяжело для фиксированного продукта |
| CDN-подключение ECharts | не хранить в репозитории | внешний домен, CSP шире, не работает в закрытом контуре | вендоринг надёжнее |

## Последствия

- ✅ Админка весит ~1 МБ (ECharts), работает в изолированной сети.
- ⚠️ Нет компонентной библиотеки — сложные формы (UI пула) потребуют больше ручного кода.

## Когда пересмотреть

Когда в админку добавится управление пулом и права — оценить переход на компонентный фреймворк.
