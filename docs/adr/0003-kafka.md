# ADR-0003. Apache Kafka как буфер и журнал событий

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Сбор событий должен отвечать быстро и не зависеть от хранилища; при сбое ClickHouse события нельзя терять; поток ~50k событий/с на пике; нужна возможность перечитать данные.

## Решение

События публикуются в Kafka (KRaft, 3 узла, RF 3, min.insync.replicas 2, топик `proview.events.v1` 24 партиции, хранение 3–7 дней); потребитель — event-ingester.

## Обоснование

- Развязка: collector отвечает 202 сразу, хранилище может быть недоступно часами — события ждут в журнале.
- Повторное воспроизведение: можно перезагрузить данные в новую схему или второй потребитель (антифрод).
- Горизонтальное масштабирование партициями; порядок событий одного показа (ключ impression_id).
- Стандарт отрасли для clickstream, оператор Strimzi снимает операционную сложность; KRaft — без ZooKeeper.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Прямая вставка в ClickHouse из collector | проще, меньше компонентов | мелкие вставки убивают MergeTree; при сбое ClickHouse — потеря или 5xx клиенту | нарушает NFR4 |
| ClickHouse async_insert | серверная буферизация мелких вставок | сбой ClickHouse = отказ приёма; нет журнала для повтора | нет развязки |
| RabbitMQ | простота, гибкая маршрутизация | нет журнала с перечитыванием, хуже на 50k msg/s с персистентностью | не даёт replay |
| NATS JetStream | лёгкий, быстрый | меньше экосистема (коннекторы, операторы, мониторинг), команда менее знакома | Kafka — стандарт для этой задачи |
| Redpanda | Kafka API, без JVM, проще | лицензия BSL у части функций | совместим — можно заменить без изменений кода |
| Apache Pulsar | tiered storage, мульти-тенантность | значительно сложнее эксплуатация (BookKeeper) | избыточно |

## Последствия

- ✅ NFR4 выполняется: chaos-тест подтверждает доставку после простоя ClickHouse.
- ⚠️ Ещё одна stateful-система: диски ~1 ТБ на брокер в проде, мониторинг лага.

## Когда пересмотреть

Если команда эксплуатации предпочтёт Redpanda — замена прозрачна (Kafka API).
