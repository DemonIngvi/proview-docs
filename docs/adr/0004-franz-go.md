# ADR-0004. Клиент Kafka: franz-go

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Нужны идемпотентный продюсер с ограниченным буфером и консьюмер-группа с ручным коммитом и контролем ребаланса; без CGO (статический бинарник).

## Решение

Используется `github.com/twmb/franz-go` (kgo) в collector и ingester.

## Обоснование

- Чистый Go, без librdkafka/CGO — статическая сборка и distroless.
- Идемпотентный продюсер по умолчанию, `MaxBufferedRecords`, `BufferedProduceRecords()` — основа обратного давления.
- `BlockRebalanceOnPoll`, `CommitRecords`, cooperative-sticky — реализуют at-least-once без гонок с ребалансом.
- Высокая производительность и активная поддержка, полный Kafka-протокол (KIP), SASL/SCRAM/TLS.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| confluent-kafka-go | официальный от Confluent, librdkafka | CGO, сложнее сборка и образ | противоречит статической сборке |
| IBM/sarama | давно используется | сложный API, исторически проблемы с консьюмер-группами и производительностью | franz-go проще и быстрее |
| segmentio/kafka-go | простой API | ограниченный контроль ребаланса и идемпотентности | не хватает для at-least-once с блокировкой ребаланса |

## Последствия

- ✅ Точный контроль семантики доставки в 150 строках кода.
- ⚠️ Специфичный API kgo — нужно знать его модели (Fetches, коммиты).

## Когда пересмотреть

Не требуется в обозримом будущем.
