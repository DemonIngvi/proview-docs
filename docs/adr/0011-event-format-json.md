# ADR-0011. Формат событий: версионированный JSON с контрактными тестами

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Контракт событий связывает SDK, collector и ingester в разных репозиториях; сегодня один потребитель топика.

## Решение

JSON-сообщения с полем `v` (=1) и ключом `impression_id`; контракт зафиксирован в документации и проверяется контрольными векторами (токен, пример сообщения) в тестах обоих сервисов и e2e-тестом.

## Обоснование

- Читаемо при отладке (kafka-console-consumer), без инфраструктуры Schema Registry.
- Объём после zstd-сжатия пачек близок к бинарным форматам (~4 МБ/с на пике).
- Правило эволюции простое: добавлять поля можно, ломать — только новым топиком.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Protobuf + Schema Registry | строгая схема, компактность, генерация кода | ещё один сервис, кодогенерация в трёх репозиториях | окупается при нескольких потребителях — запланировано в развитии |
| Avro + Schema Registry | эволюция схем, экосистема Kafka Connect | то же + менее удобен в Go | нет Connect в архитектуре |
| MessagePack/CBOR | компактно, без схемы | хуже инструменты отладки, выигрыш съедает сжатие | незначимый выигрыш |

## Последствия

- ✅ Простая отладка и отсутствие лишней инфраструктуры.
- ⚠️ Схема проверяется тестами, а не брокером; дисциплина эволюции обязательна.

## Когда пересмотреть

Когда у топика появится второй-третий потребитель (антифрод, биллинг).
