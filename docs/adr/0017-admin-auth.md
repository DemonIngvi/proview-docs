# ADR-0017. Доступ к админке: Basic-auth или SSO на ingress

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Админкой пользуются внутренние сотрудники; в компаниях обычно есть SSO; встраивать полноценный OIDC в каждый сервис дорого.

## Решение

Встроенная Basic-аутентификация (сравнение за постоянное время, пароль из Secret) для простых установок; в production — SSO через oauth2-proxy на ingress (`auth-url`) и `AUTH_DISABLED=true` в сервисе.

## Обоснование

- SSO централизует пользователей, MFA и аудит без кода в сервисе.
- Basic-auth делает систему безопасной по умолчанию даже без SSO.
- Сервис отказывается стартовать без пароля, если явно не отключена аутентификация.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Встроенный OIDC-клиент | без прокси | код сессий, refresh-токенов, CSRF в каждом сервисе | прокси решает это один раз |
| Без аутентификации, только сеть | просто | любой из внутренней сети видит коммерческие данные | неприемлемо |

## Последствия

- ✅ Одна настройка ingress для любого IdP (Keycloak, Google, Azure AD).
- ⚠️ Нет ролевой модели внутри админки (все видят все баннеры).

## Когда пересмотреть

Когда понадобится разграничение по рекламодателям — роли из claims SSO-заголовков.
