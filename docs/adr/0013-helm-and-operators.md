# ADR-0013. Helm-чарт на сервис + umbrella; инфраструктура через операторы

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Нужна удобная доставка в произвольный Kubernetes, независимые релизы сервисов и надёжные Kafka/PostgreSQL/ClickHouse.

## Решение

Каждый сервис публикует свой Helm-чарт (OCI, GHCR) из своего репозитория; `proview-deploy` содержит umbrella-чарт с зависимостями и ресурсами операторов Strimzi, CloudNativePG, Altinity clickhouse-operator; профили dev/prod.

## Обоснование

- Сервис выпускается и откатывается независимо; umbrella фиксирует совместимый набор версий.
- Операторы реализуют failover, обновления, бэкапы — то, что нельзя надёжно сделать StatefulSet-ом вручную.
- OCI-реестр GHCR — один реестр для образов и чартов.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Kustomize | без шаблонов, патчи | нет версионирования пакетов и зависимостей, хуже параметризация для чужой инфраструктуры | Helm удобнее для дистрибуции |
| Bitnami-чарты Kafka/PostgreSQL/ClickHouse | быстро | с 2025 г. изменилась политика публикации образов Bitnami (бесплатные — только ограниченный набор/legacy), StatefulSet без операторской логики failover | риск поставки и слабее эксплуатация |
| Управляемые облачные сервисы (MSK, Cloud SQL, ClickHouse Cloud) | нет эксплуатации | привязка к облаку, стоимость, требование своей инфраструктуры | не подходит как базовый вариант; чарт позволяет отключить infra и указать внешние адреса |
| Argo CD ApplicationSet без Helm | GitOps | всё равно нужен формат пакета | дополняет Helm, а не заменяет |

## Последствия

- ✅ Установка всей системы одной командой; инфраструктура декларативна.
- ⚠️ Операторы ставятся заранее (cluster-scoped CRD) — это шаг платформенной команды.

## Когда пересмотреть

При переходе на GitOps — Argo CD Application поверх этого же umbrella-чарта.
