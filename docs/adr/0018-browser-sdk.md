# ADR-0018. SDK: ES-модуль без зависимостей, IntersectionObserver и sendBeacon

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

SDK встраивается на чужие сайты: должен быть маленьким, не тормозить страницу, корректно измерять видимость и не терять события при уходе.

## Решение

Три ES-модуля без зависимостей (~8 КБ): трекер и очередь — чистые классы с тестами на фиктивных часах; DOM-слой — IntersectionObserver, pointer-события, visibilitychange/pagehide; отправка `text/plain` через fetch keepalive и `navigator.sendBeacon`.

## Обоснование

- IntersectionObserver — нативное и дешёвое измерение видимости по IAB без опроса скролла.
- `text/plain` не вызывает CORS-preflight — один запрос вместо двух на каждый пакет.
- sendBeacon доставляет события при закрытии вкладки; повторы с тем же seq сохраняют event_id.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Пиксель-изображение (GET) | работает везде | нет тела, ограничение длины URL, кэширование, нет пакетов | не годится для длительностей и пакетов |
| Google Tag Manager / сторонний счётчик | без разработки | данные у третьей стороны, нет нашего токена | противоречит цели продукта |
| Сборка (TypeScript + бандлер) | типизация | цепочка сборки для ~300 строк | можно ввести при росте SDK |

## Последствия

- ✅ Логика трекинга покрыта 11 unit-тестами без браузера.
- ⚠️ Без сборки нет минификации — решается CDN-сжатием (gzip/brotli).

## Когда пересмотреть

Если SDK вырастет (видео-форматы, consent API) — TypeScript и сборка.
